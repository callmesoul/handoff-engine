> 它只调用 `handoffctl deliver`，由 CLI 负责部署对齐、环境漂移判定和结构化验收。
> 正文保留作为早期设计的历史记录。

参数是交接单 id。没给就问我。

## 1. 拿任务单

```
git -C <交接仓路径> pull
```

读 `tasks/<id>.json`。状态不是 `merged` 就说明后端还没交付完，告诉我当前状态，然后等。

## 2. 等部署对齐

看 `result.commit_sha`。对 dev 环境的版本接口发 GET，拿它报的 sha，跟 commit_sha 比前七位。

间隔五秒，最多十五分钟。

超时就告诉我「部署没完成」，不是「验收通过」。这两句差别很大。

如果 dev 环境没有版本接口，只能确认状态到了 `merged`。明确告诉我这一条没验到，别含糊过去。

## 3. 跑验收

`acceptance.checks` 每条单独执行，`{{base_url}}` 换成验收环境地址。

逐条报 PASS / FAIL。失败的把输出原文附上，不要总结。

## 4. 三种结果

**全绿**：把后端交付接回来，按 `contract` 对齐前端这边的调用代码。

**有失败**：贴失败的命令和输出原文，附上 `deploy_sha`。我要判断是环境漂移还是真没做好。

**后端 failed**：把 `result.notes` 原文给我，那里是后端 codex 的报错。

## 不要

别改后端代码。有意见写进备注，让人去沟通。
